# Feature: Formula 1

Sources: Jolpica (schedule, results, standings) + OpenF1 (laps, stints, location; free from 30 min after session end, 2023+). See [DATA-SOURCES.md §3–4](../DATA-SOURCES.md#3-jolpica-f1-api-schedule-results-standings).

## 1. Race weekend schedule
- Weekend card: GP name, circuit, local dates; sessions (FP1–3 or FP1 + Sprint Qualifying + Sprint, Qualifying, Race) with local times and countdown to the next one.
- Session durations for `ends_at` estimation: FP 60 min, SQ 45, Sprint 60, Q 60, Race 120 (adjusted when results arrive).
- Notifications: 30 min before Q, SQ, Sprint, Race; 120 min before Race (editable via `event_reminder_rule`). FP: none.
- All sessions are "followed" (appear in iCal sports feed and calendar).

## 2. Results & standings
- Session results: classification (pos, driver, team, time/gap, points, status), qualifying Q1/Q2/Q3.
- Result availability: poll OpenF1 `session_result` from session end + 35 min (fast), then Jolpica for canonical points (+ standings) until present (max +12 h). `f1_result` notification fires once (spoiler-aware).
- Drivers' and constructors' championships with snapshots per round (spoiler: as of last visible race).

## 3. Driver comparison (2 drivers, current season by default)
| Metric | Source | Notes |
|---|---|---|
| Season points & points progression chart | Jolpica results (race + sprint) | |
| Qualifying head-to-head | Jolpica qualifying | best of Q3>Q2>Q1 position per round |
| Race head-to-head, average finishing position | Jolpica results | DNFs excluded from average, counted separately |
| Lap time comparison for a chosen session | OpenF1 `laps` | 2023+; pit in/out laps excluded; line chart |
| Tyre strategy for a chosen race | OpenF1 `stints` | stacked bar per driver |
- Only rounds whose race is visible (spoiler) are included.
- OpenF1 results cached permanently; on-demand fetch respects 30 req/min (per-source limiter; UI shows loading state).

## 4. Track overview
- Name, locality, country, map coordinates (text only), **length** (curated `circuit-facts.ts`; hidden if missing), **laps** (winner's laps from the most recent race at this circuit), **past winners** (last 10, Jolpica), **weekend weather** (Open-Meteo at circuit coordinates, shown when the race is ≤ 16 days away; daily max/min, precipitation probability for Fri–Sun).
- **Track outline**: generated from OpenF1 `location` for one driver's fastest clean lap of the most recent session at the circuit (2023+): x/y points → normalised to 0..1000 → downsampled (Ramer–Douglas–Peucker, ≤ 600 points) → stored once in `f1_circuit_outline` → rendered as SVG `<path>`. No copyrighted images.
- Circuits never raced since 2023 → no outline ("outline available after first session").

## Edge cases
- Sprint weekends detected by presence of `Sprint` in schedule (`f1_weekend.is_sprint`).
- Session rescheduled/cancelled (weather) → schedule sync updates times; cancelled sessions marked, notifications cancelled.
- Driver mid-season swap → comparison handles drivers with fewer rounds (per-round alignment, gaps shown).
- OpenF1 `session_key` mapping by (year, country/circuit, session name, date) — mismatch logged, feature degrades.

## Acceptance criteria
- [ ] Schedule mapper tests (sprint and normal weekend fixtures) and local-time rendering.
- [ ] Comparison aggregates unit-tested (H2H with missing rounds, DNF handling, hidden rounds excluded).
- [ ] Outline generation unit-tested (normalisation, RDP point limit, closed loop).
- [ ] Result notification fires exactly once even when both OpenF1 and Jolpica deliver.
