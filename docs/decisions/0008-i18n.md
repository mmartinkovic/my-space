# ADR 0008 — Internationalisation: own typed dictionaries (sk + en)

- Status: Accepted
- Date: 2026-11-25

## Context
UI must be available in Slovak and English. Texts are also produced by the backend (Telegram, Web Push, morning brief) and later by Expo. Single user → locale is a user setting, not a URL segment.

## Decision
- `packages/core-i18n`: `sk` dictionary is the source; `en` is typed as `Dictionary` (`satisfies`) so a missing key fails typecheck. Messages with parameters are functions `(p: { count: number }) => string`, plural rules via `Intl.PluralRules`.
- Formatting exclusively via `Intl.DateTimeFormat`, `Intl.NumberFormat` (EUR), `Intl.RelativeTimeFormat` with explicit `timeZone: 'Europe/Bratislava'`.
- Locale stored in `app_settings.locale` (`sk` | `en`, default `sk`); before login, `Accept-Language` decides.
- No i18n library: avoids a dependency, works identically in Node, browser and React Native.

## Alternatives
- `next-intl` — good for Next, but not usable in the backend renderer or Expo; URL-based routing is unnecessary. Rejected.

## Consequences
- + Compile-time completeness of translations.
- − No ICU message syntax; complex sentences are written as functions.
